# B-23 — Hooks locaux portables (pre-commit du repo, pas seulement la machine de Nathan)

Backlog `manifests/backlog.yaml` (phase P2-gouvernance). Origine : audit du backlog demandé
par Nathan après I18N-031, pour identifier ce qu'il restait à faire sur ForgeAI Toolkit.

## 1. État mesuré

Les hooks git **globaux** (`core.hooksPath` → `~/proof-method/git-hooks`, machine de Nathan)
sont déjà actifs et couvrent largement les critères de B-23 (gitleaks, no-stub-scan,
docs-drift, gate registres) — confirmé en lisant leur contenu directement. Mais ce sont des
hooks **hors du repo**, personnels à Nathan : un clone frais par quiconque d'autre (ou tout
outil qui n'a pas ce `core.hooksPath`) n'en bénéficie pas.

Le repo porte déjà `.pre-commit-config.yaml` (framework `pre-commit`, portable, standard —
n'importe qui peut l'activer via `pre-commit install`), mais avec une seule vérification
(ggshield). `scripts/no_stub_scan.py` existe déjà **dans le repo**, déjà testé
(`tests/test_no_stub_scan.py`), déjà utilisé par le job CI `no-stub-scan` — donc pleinement
repo-portable, contrairement aux hooks globaux.

`ruff` est déjà une dépendance dev (`pyproject.toml`) mais **aucune config `[tool.ruff]`
n'existe**, et aucun job CI ne lint le repo. Mesuré : `ruff check` avec les réglages PAR
DÉFAUT sur `src/`+`scripts/` = 411 erreurs, dont 232 rien que du dépassement de longueur de
ligne (E501) et ~140 de modernisation de type hints (UP0xx) — du style, pas des bugs, jamais
appliqué nulle part avant. Sous un jeu de règles minimal `E9`+`F` (erreurs de syntaxe +
pyflakes = bugs réels) : 27 erreurs sur `src/`+`scripts/`, et 59 de plus une fois `tests/`
inclus (révélé seulement en exécutant le hook réel `--all-files`, pas seulement mon périmètre
de mesure initial).

## 2. Décision de conception

### Décision — `select = ["E9", "F"]`, jamais les réglages par défaut
Un gate qui bloque 411 lignes de style jamais appliqué nulle part casserait le premier commit
de quiconque sur un fichier existant, pour du bruit sans rapport avec son diff. `E9`+`F`
(pyflakes : imports/variables non utilisés, noms non définis, redéfinitions) attrape des
**bugs réels**, jamais du style — c'est la seule chose qu'un hook LOCAL bloquant devrait
imposer rétroactivement sur un gros codebase jamais linté avant.

### Réfutation — exclure `tests/` du hook plutôt que le corriger
Écarté après mesure : les 59 violations de `tests/` sont **exactement les mêmes catégories**
déjà validées sûres dans `src/`/`scripts/` (F401 import inutilisé, F811 redéfinition) —
aucune raison de traiter `tests/` différemment. Exclure `tests/` aurait été une incohérence
arbitraire (« le lint protège le produit mais pas ses propres tests ») sans bénéfice réel.

### Trouvaille pendant l'application — un vrai bug latent
`src/forgeai/deploy/compose.py:92` : `svc: "ServiceSpec"` en annotation différée
(`from __future__ import annotations` actif) alors que `ServiceSpec` n'était **jamais
importé** dans ce fichier — `forgeai.core.models` (qui le définit) était déjà importé pour
`DeploymentPlan, HealthState, ProbeType` juste au-dessus. Sans crash à l'exécution (les
annotations en chaîne ne sont pas évaluées), mais tout outil qui introspecte le type
(`typing.get_type_hints`, mypy, un IDE) casserait. Corrigé par un seul ajout à la ligne
d'import existante. C'est précisément le genre de défaut que ce gate est censé attraper.

`ruff --fix` a par ailleurs supprimé `DeploymentPlan` de la même ligne d'import — vérifié
directement (`grep DeploymentPlan compose.py` → zéro occurrence après le fix) : import mort
préexistant, sans rapport avec cette story, retrait sûr et confirmé par une recherche
exhaustive, pas seulement la confiance en l'outil.

### Objection round 1 vérifiée et réfutée — `ServiceSpec` dans `test_wizard_health.py`
Qwen3.8-Max a objecté que le retrait de `ServiceSpec` d'une ligne d'import (ligne 69,
`from forgeai.core.models import HealthState, ProbeType, ServiceSpec` → sans `ServiceSpec`)
casserait les appels `ServiceSpec(...)` plus loin dans le fichier. Vérifié directement :
**faux** — ligne 3 du même fichier (hors de la fenêtre de contexte du diff montré au
reviewer) importe déjà `ServiceSpec` au niveau module
(`from forgeai.core.models import DeploymentPlan, ServiceSpec, RenderTarget`). La ligne 69
était une **réimportation redondante** ajoutée plus tard dans le fichier pour introduire
`HealthState`/`ProbeType` (eux non importés en ligne 3) — ruff a correctement gardé ces deux
noms et retiré uniquement le doublon `ServiceSpec`, exactement le comportement attendu de
F811. Confirmé par l'exécution réelle : la suite complète (§7) passe `rc=0`, y compris tous
les tests de ce fichier qui appellent `ServiceSpec(...)`. Aucune modification de code
nécessaire — la story documente la vérification pour la traçabilité, pas pour contredire le
reviewer sans preuve.

### Round 2 — 5 objections mineures, toutes vérifiées et corrigées

**APPROVE 2/3** (DeepSeek-V4-Pro, Gemini-3.1-Pro), **REJECT** Qwen3.8-Max :

1. **[mineure, CONFIRMÉE — procédural] CA1 sans preuve de compilation.** Juste : aucune sortie
   `py_compile` n'était jointe. **Corrigé** : compilation explicite des 41 fichiers `.py`

   sortie complète.** Juste. **Corrigé** : `pre-commit run --all-files --verbose` capturé
   intégralement (durées, détail par hook — « No secrets have been found »,
   « 325 fichiers scannés, zéro violation », etc.), voir §7.
3. **[mineure, CONFIRMÉE] Commentaire obsolète dans `k3s.py`.** Vérifié exact : le commentaire
   « Import local pour éviter cycles... » expliquait des imports locaux que le round 1 avait
   déjà retirés (F811). **Corrigé** : commentaire orphelin supprimé.
4. **[mineure, CONFIRMÉE] Titre de §3 trompeur — mélange changements authorés et
   mécaniques.** Juste, corrigé en §3 (deux catégories distinguées explicitement : 3 fichiers
   purement authorés, `k3s.py` hybride authoré+mécanique, 39 purement mécaniques).
5. **[mineure, CONFIRMÉE — procédural, et une découverte permanente utile] Pas de ligne
   native pytest « N passed ».** Vérifié la cause exacte cette fois plutôt que de simplement
   ajouter un résumé maison par-dessus : `pyproject.toml` impose `addopts = "-q"` à **toute**

   de pytest (9.1.1) — pas une troncature, pas un défaut de pytest-cov (vérifié en répétant
   sans aucune option de couverture : même absence). **Corrigé** : `-o addopts=""` neutralise
   le défaut du projet pour cette seule invocation → `1843 passed, 7 skipped, 3 warnings in
   207.27s`, cohérent au chiffre près avec les 1850 recomptés indépendamment tout du long de
   cette session (1843+7=1850). Incantation à retenir pour toute preuve future sur ce dépôt.
