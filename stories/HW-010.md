# HW-010 — NVIDIA présent-mais-non-qualifié : refuser, ne pas disparaître (FAI-U-010)

## Cause racine
Quand `nvidia-smi` échoue/est absent, le GPU NVIDIA est vu par lspci (HW-009) avec `vram_mb == 0`.
`derive_profile` le jugeait inutilisable (seuil 8192) et retombait SILENCIEUSEMENT sur `minimal-cpu` :
la RTX DISPARAISSAIT du plan. Or `nvidia-smi` donne toujours la VRAM réelle si le driver fonctionne ;
`vram_mb == 0` pour un NVIDIA vu par lspci = VRAM INCONNUE (driver KO), pas zéro réel.

## Changement (séparer présence PCI / runtime / VRAM par la PROVENANCE)
- `detect.py::_pci_gpus` : un NVIDIA vu par lspci reçoit le marqueur canonique ` [unqualified]` dans le
  nom (nvidia-smi ne l'a pas rapporté → driver/runtime KO). `detect_gpus` n'ajoute ce NVIDIA que si
  nvidia-smi a échoué (seen_nvidia) : le marqueur n'apparaît donc QUE lorsqu'il est réellement non qualifié.
- `profile.py::derive_profile` : si aucun GPU utilisable ET qu'un NVIDIA `[unqualified]` est présent,
  lève `ProfileError` avec un diagnostic orientant vers le driver/runtime (au lieu de retomber muet sur CPU).

## Pourquoi la provenance (et pas `vram_mb == 0` nu)
Un NVIDIA SYNTHÉTIQUE `GPU("nvidia","carte",0)` (test_profile_presence, hors périmètre, immuable) doit
rester `minimal-cpu`. Le marqueur `[unqualified]` — émis UNIQUEMENT par la sonde lspci réelle —
distingue « présent-non-qualifié » d'un simple vram=0 sans provenance. Aucun fichier hors périmètre modifié.
