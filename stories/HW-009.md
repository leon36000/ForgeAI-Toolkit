# HW-009 — Classer les iGPU par identifiants PCI (FAI-U-009)

## Cause racine
`planner/profile.py::_is_igpu` classait iGPU/dGPU par sous-chaînes du NOM ('igpu'/'integrated'), mais
`hardware/detect.py::_pci_gpus` produit un nom tronqué issu de `lspci -nn` ('Advanced Micro Devices,
Inc. ... Device') qui ne porte JAMAIS ces marqueurs. Un iGPU AMD (PCI [1002:13c0] Raphael, VRAM
inconnue=0) était donc PROMU à tort en dGPU utilisable -> profil minimal-gpu-rocm au lieu de minimal-cpu.
Le test de « couverture » existant (test_planner_profile.py) utilisait un nom synthétique 'Raphael iGPU'
que le vrai chemin lspci ne produit jamais -> fausse couverture.

## Changement
- `detect.py` : table `_INTEGRATED_PCI_DEVICE_IDS` (iGPU/APU AMD connus, par identifiant PCI
  vendor:device). `_pci_gpus` extrait l'id PCI complet et l'encode dans le nom
  (`... [vendor:device]`), avec suffixe canonique ` [integrated]` si le device est un iGPU connu.
- `profile.py` : `_is_igpu` remplacé par `_est_integre` qui lit le marqueur `[integrated]` (source
  d'autorité = classification PCI de detect), sous-chaînes en repli défensif. `_usable` inchangé sinon.
- Le dataclass `GPU` (core/models.py, hors périmètre) ne peut pas gagner de champ : la classification
  est transportée par le champ `name`, de façon structurée et parseable.
