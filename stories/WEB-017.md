# WEB-017 — Politique d'accès aux GET sensibles

- **Issue** : #250 · **Tier** : T2 (sécurité — confidentialité : fuite de données d'infrastructure)
- **Dépend de** : WEB-001 (auth web : `authorize_mutation`, jeton Bearer, anti-CSRF/rebinding) — mergé.
- **Reprise lane CODEX** · **Périmètre** : `src/forgeai/web/server.py`,
  `tests/test_web017_get_policy.py` (nouveau), `stories/WEB-017.md`.

## 1. Problème (code réel)
`web/server.py` protège les MUTATIONS (`do_POST` → `_guard_mutation` → `authorize_mutation` :
jeton Bearer temps-constant, anti-CSRF `Sec-Fetch-Site`/`Origin`, anti-DNS-rebinding `Host`). Mais
`do_GET` ne garde AUCUNE route. Or plusieurs GET exposent des données d'infrastructure sensibles :
`/api/detect` (empreinte matérielle), `/api/models` (routes/endpoints des modèles configurés),
`/api/models/local`, `/api/engines`, `/api/engines/compatible`, `/api/stacks[/*]`,
`/api/stacks/recommended`, `/api/spheres`, `/api/nodes/status`, `/api/nodes/receptacles`,
`/api/nodes/prepare/*`. Sur un bind non-loopback (`--host 0.0.0.0`) ils fuient l'infra à tout client
réseau non authentifié ; sur un bind loopback ils restent lisibles par **DNS-rebinding** depuis un
site malveillant que la victime visite.

## 2. Décision (design — autorité orchestrateur)
**Les GET sensibles réutilisent EXACTEMENT la garde des mutations (`_guard_mutation`), inchangée.**

- **Classification (fail-closed par préfixe `/api/`)** : un chemin est *sensible* s'il commence par
  `/api/` ET n'est pas `/api/health` ni sous `/api/i18n/`. Tout le reste — coquille UI (`/`,
  `/index.html`), assets statiques (fallthrough `_asset_bytes` : app.css/app.js/adoption.js),
  `/api/health` (sondes), `/api/i18n/*` (traductions pré-auth) — est *public*. Un futur `/api/*`
  est sensible PAR DÉFAUT (aucune fuite par omission).
- **Politique** : garde unique en tête de `do_GET`, avant toute route :
  `if _is_sensitive_read_path(path) and not self._guard_mutation(): return`. Codes 401 (jeton
  manquant/invalide) / 403 (rebinding/CSRF) hérités tels quels. Loopback sans jeton : lecture
  autorisée (UI locale) SAUF rebinding (`Host` hors allowlist → 403).

### 2b. Réfutation de la relaxation « pas de CSRF sur un GET » (mesurée)
Une proposition d'architecture suggérait un helper `_authorize_read` *relâché* omettant l'anti-CSRF
ET l'anti-rebinding `Host` au motif qu'« un GET ne mute pas l'état ». **Rejeté.** WEB-017 traite la
**confidentialité**, pas l'intégrité. L'attaque de référence contre un serveur lié en loopback est le
**DNS-rebinding** : `evil.com` re-résout vers `127.0.0.1`, le navigateur croit être same-origin, et
le JS de `evil.com` LIT la réponse de `/api/detect`. La SEULE défense est la vérification `Host ∈
allowlist` — précisément celle que la relaxation supprimait. Mesure : dans `authorize_mutation`, sous
la branche loopback-sans-jeton, `Sec-Fetch-Site` vaut `same-origin` après rebinding (NON rejeté) ;
c'est le contrôle `Host` qui bloque. Donc réutiliser la garde de mutation telle quelle est à la fois
plus SIMPLE (aucun helper à écrire/tester) et plus SÛR (rebinding fermé). Justification #3 de l'ADR
d'origine (« entretien unique ») est mieux servie par la réutilisation littérale.

### 2c. Réfutation mesurée d'une objection de revue (encodage URL)
Un relecteur (Qwen3.7-Max, verdict APPROVE) a signalé une objection *mineure* : un chemin
percent-encodé `/%61pi/detect` (= `/api/detect`) ne matche pas `_is_sensitive_read_path`
(`startswith("/api/")` sur le chemin brut) et pourrait contourner la garde *si le routage en aval
décodait le chemin*. **Réfuté par mesure** (bind non-loopback, sans jeton) :
`GET /api/detect` → 401 (gardé) ; `GET /%61pi/detect` → 404 ; `GET /api%2Fdetect` → 404. La garde
ET les routes utilisent le MÊME `parsed.path` brut (non décodé) : tout ce qui échappe à la garde par
encodage rate aussi le handler sensible → 404, jamais une fuite. La cohérence brut↔brut est la
propriété correcte ; décoder avant la garde SANS décoder au routage créerait précisément la
divergence redoutée. Aucun changement de code requis.

## 3. TDAD (RED d'abord) — `tests/test_web017_get_policy.py`
Miroir des tests existants `tests/test_web_auth.py` (fixtures `live`/`live_non_loopback`,
`test_post_host_rebinding_rejete`). Groupes :
- **G1 public loopback** : `GET /api/health` sans jeton → 200 (jamais gardé).
- **G2 public assets** : `GET /app.css`, `GET /app.js` sans jeton → 200 (UI).
- **G3 public i18n** : `GET /api/i18n/fr` sans jeton → 200.
- **G4 sensible hors-loopback sans jeton** : bind non-loopback, `GET /api/detect` sans Authorization → 401.
- **G5 sensible hors-loopback avec Bearer valide** → 200.
- **G6 sensible loopback (UI locale)** : `GET /api/detect` sur 127.0.0.1 sans jeton → 200.
- **G7 anti-rebinding (LE test-clé)** : loopback, `GET /api/detect` avec `Host: evil.com` → 403.
  (C'est le test que la relaxation « drop Host » ferait échouer.)
- **G8 classification** : `_is_sensitive_read_path` — table `/api/detect`,`/api/models`,`/api/nodes/status`
  → True ; `/`,`/index.html`,`/app.js`,`/api/health`,`/api/i18n/fr` → False.
- **G9 point d'application réel** : la garde est en tête de `do_GET` (assertion `inspect.getsource`
  ou test live traversant une route sensible réelle) — pas seulement testée en isolation.
- **Mutation** : retirer l'appel de garde dans `do_GET` (ou faire renvoyer True à la classification
  sur un chemin public) → G4/G7 tombent.

## 4. Critères d'acceptation
- **CA1** GET sensibles (`/api/*` hors health/i18n) soumis à la MÊME politique que les mutations :
  401 sans jeton hors-loopback, 403 sur rebinding `Host`, 200 en loopback local sans jeton.
- **CA2** GET publics (coquille UI, assets, health, i18n) toujours 200 sans jeton.
- **CA3** classification fail-closed : tout futur `/api/*` non listé est sensible par défaut.
- **CA4** non-régression : `test_web_auth`, `test_web_server`, `test_web_nodes` verts ; suite complète
  verte, no-stub, couverture ≥ 85 %.
