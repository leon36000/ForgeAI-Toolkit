## 1. Problème (constaté dans le code réel)

`main()` (src/forgeai/cli.py:1523-1529) dispatche `return args.func(args)` sous un unique
`except DeployError` qui, en plus d'être étroit, **interpole `{exc}` sans rédaction** (proof:allow — exemples de fuite en prose) :

```python
    try:
        return args.func(args)
    except DeployError as exc:
        print(f"ECHEC DEPLOIEMENT: {exc}", file=sys.stderr)   # fuite potentielle de secret
        return 8
```

Toute AUTRE exception inattendue (dans n'importe lequel des ~40 handlers `_xxx(args)->int`) remonte
en **traceback Python brute** jusqu'à `sys.exit(main())` : illisible pour l'utilisateur ET fuite du
secret si un message d'exception l'a interpolé (`api_key=…`, `Bearer …`). <!-- proof:allow : exemple prose -->

## 2. Décision d'architecture (une justification par point)

1. **Structure — rename + wrapper.** Le corps actuel de `main()` (construction du parser + `parse_args`
   + `set_locale` + dispatch) est renommé `_run(argv: list[str] | None) -> int`. `main(argv=None) -> int`
   devient un mince wrapper `try/except`. *Justif :* une frontière NOMMÉE et unique est greppable,
   testable en isolation et impossible à contourner par un `return` interne ; envelopper seulement la
   ligne de dispatch laisserait échapper une exception survenant pendant la construction du parser.

2. **Exceptions capturées, dans cet ordre, dans `main`.** DEUX clauses seulement :
   - `except KeyboardInterrupt:` → message propre sur stderr, `return 130`. *Justif :* code SIGINT
     conventionnel ; `KeyboardInterrupt` est un `BaseException` (pas un `Exception`) : sans clause
     dédiée il produirait une traceback — clause donc PORTEUSE (prouvée par mutation, cf. §5).
   - `except Exception as exc:` → LA frontière (voir 3-4). *Justif :* `Exception` — et NON
     `BaseException` — est la largeur exacte : `SystemExit(2)` d'argparse n'étant pas une `Exception`,
     il traverse intact (CA3/G4). Élargir à `BaseException` avalerait cet exit : prouvé par la mutation
     `except Exception → except BaseException` qui fait tomber G4.
   - **Pas de `except SystemExit: raise` explicite.** Une telle clause serait comportementalement
     REDONDANTE avec `except Exception` (SystemExit ∉ Exception, jamais capturé) : la mutation qui la
     retire ne fait tomber aucun test (survivante). Conformément à la discipline « aucune ligne non
     détectable », elle est ÉCARTÉE ; la préservation de l'exit argparse est garantie par la largeur
     `except Exception` ci-dessus (elle, prouvée détectante) et documentée en commentaire dans le code.

3. **Échappatoire diagnostic — `FORGEAI_DEBUG`.** Si `os.environ.get("FORGEAI_DEBUG")` est non vide,
   la frontière fait `raise` (traceback complète restaurée). *Justif :* variable d'env = surface nulle,
   couvre aussi une panne pré-dispatch, pas de flag à câbler dans chaque sous-parser.

4. **Message + rédaction + code retour.** Sinon :
   `print(f"ERREUR: {redact_exception(exc)}", file=sys.stderr)` puis `return 1`.
   *Justif :* `redact_exception` rend `"{Classe}: {message rédigé}"` — le minimum diagnostique (type +
   message sûr) sans traceback ; `1` = échec générique, distinct des codes métier 6/7/8/9/12.

5. **Handler `DeployError` — trou refermé en place.** Reste dans `_run` (message + code 8 spécifiques
   préservés), mais `{exc}` → `redact_text(str(exc))` :
   `print(f"ECHEC DEPLOIEMENT: {redact_text(str(exc))}", file=sys.stderr)`. *Justif :* on conserve le
   format et le code exacts, on ne rédige que la valeur — compatibilité totale.

6. **Aucune adoption hors `main()`.** La frontière unique + la correction DeployError couvrent la
   catégorie « erreurs CLI ». Les handlers qui écrivent eux-mêmes sur stderr avant de retourner un code
   sont hors périmètre (suivi ERR-041B/C) — noté en risque.

## 3. Stratégie TDAD (le crew écrit `tests/test_cli_error_boundary.py` AVANT le code)

Conventions : `import forgeai.cli as cli` ; `code = cli.main([...])` ; `capsys.readouterr()` ;
injection d'exception par `monkeypatch.setattr(cli, "<handler>", ...)`.

- **G1 — inattendue rédigée sans traceback :** handler monkeypatché levant
  `RuntimeError("api_key=" + "h"*32)` <!-- proof:allow : exemple TDAD --> → `cli.main([...])` retourne 1 ; stderr NE contient PAS
  "Traceback" ; contient "«REDACTED»" ; le secret et ses fenêtres de 8 caractères sont absents.
- **G2 — formes secrètes :** message d'exception avec `Bearer …`, `sk-…`, `token=…` → valeurs absentes de stderr.
- **G3 — FORGEAI_DEBUG :** `monkeypatch.setenv("FORGEAI_DEBUG","1")` + handler qui lève →
  l'exception se propage (`pytest.raises(RuntimeError)`) OU "Traceback" présent : la frontière est bypassée.
- **G4 — SystemExit argparse préservé :** `cli.main(["commande-inexistante"])` → `pytest.raises(SystemExit)`
  code 2 ; la frontière ne le convertit pas en 1.
- **G5 — KeyboardInterrupt :** handler levant `KeyboardInterrupt` → retour 130, message propre, pas de traceback.
- **G6 — non-régression des codes :** un handler monkeypatché `return 9` (et `return 0`) → `main` retourne
  9 (resp. 0) inchangé : un int retourné n'est jamais confondu avec une levée.
- **G7 — DeployError porteur d'un jeton :** handler levant `DeployError("...api_key=" + "h"*32)` <!-- proof:allow : exemple TDAD --> → stderr
  "ECHEC DEPLOIEMENT: …" avec secret rédigé, code 8 (trou actuel refermé).

## 4. Critères d'acceptation (testables)

- **CA1** exception inattendue → aucune traceback sur stderr, message rédigé, code non nul (1).
- **CA2** `FORGEAI_DEBUG=1` → traceback complète restaurée.
- **CA3** `SystemExit(2)` d'argparse préservé (pas de conversion).
- **CA4** codes de retour existants (0/6/7/8/9/12) inchangés à travers la frontière.
- **CA5** message `DeployError` rédigé (fuite `{exc}` refermée).
- **CA6** aucun secret ni fenêtre de 8 caractères dans une sortie d'erreur.
- **CA7** suite de tests complète verte ; no-stub OK ; couverture ≥ 85 %.

## 5. Risques

- Sur-capture : `except Exception` (jamais `BaseException`) laisse `SystemExit` traverser intact ;
  `KeyboardInterrupt` est traité par sa clause dédiée placée avant la frontière (ordre §2, prouvé §5).
- Confusion int-retourné / exception-levée : couvert par G6 (non-régression).
- Fuite résiduelle en amont de la frontière (handler écrivant sur stderr lui-même) : hors périmètre,
  suivi ERR-041B/C.
