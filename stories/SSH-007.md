# SSH-007 — Remplacer le TOFU SSH par un enrôlement d'empreinte explicite

- **Issue** : #225
- **Tier** : T2 (sécurité — élimination d'une fenêtre MITM au premier contact SSH)
- **Dépend de** : ORCH-001 (mergé).
- **Reprise lane CODEX** (Codex retiré).
- **Périmètre fichiers** : `src/forgeai/network/remote_probe.py` (SshRunner), `src/forgeai/cli.py`
  (`_node_probe`, `_node_discover` + leurs sous-parsers), `tests/test_ssh007_hostkey.py` (nouveau),
  `stories/SSH-007.md`.

## 1. Vulnérabilité (code réel)

`SshRunner.run` (remote_probe.py:34) lance `ssh … -o StrictHostKeyChecking=accept-new …` — un **TOFU**
(Trust On First Use) : la clé d'hôte est acceptée aveuglément au premier contact, ouvrant une fenêtre
MITM. `SshRunner` est instancié par DEUX appelants : `_node_probe` (cli.py:644) et `_node_discover`
(cli.py:752, chemin nœud distant). Les deux sont vulnérables.

Le précédent sécurisé `network/bootstrap.py` (EX-1) impose `StrictHostKeyChecking=yes` + known_hosts
dédié + empreinte SHA256 exigée à l'avance (`render_join_plan` lève si l'empreinte manque).

## 2. Décision d'architecture (une justification par point)

> **Provenance** : ADR crew (DeepSeek). L'Orchestrateur **écarte l'option B** proposée par l'architecte
> (fournir une ligne known_hosts complète) au profit de l'**option A (enrôlement par empreinte SHA256)**,
> pour trois raisons : (a) la story exige littéralement « enrôlement d'**empreinte** » ; (b) **cohérence
> de la surface** : `node tailscale --hostkey` prend déjà une empreinte « SHA256:… » — `node probe`/`discover`
> doivent l'imiter ; (c) une empreinte courte est le format standard de vérification humaine (vs une clé
> base64 longue). Option B (plus petit TCB, sans keyscan) est notée comme durcissement alternatif ; la
> revue scellée arbitre. Coût maîtrisé : le motif d'extraction d'empreinte existe déjà (`node_add.key_fingerprint`).

1. **Signature.** `SshRunner.__init__(user, host, keyfile, hostkey_sha256, timeout_s=20.0)`. Le paramètre
   `hostkey_sha256` est REQUIS et validé : DOIT commencer par « SHA256: » (ssh-keygen n'émet que du SHA256 ; « MD5:… », « foo:bar », vide → refus) ; format invalide/absent →
   `RemoteProbeError` **avant tout appel réseau**. *Justif :* pas d'enrôlement possible sans ancre déclarée.

2. **Enrôlement (option A).** À la première `run()` (ou à l'init), `SshRunner` :
   - `ssh-keyscan -t ed25519,ecdsa,rsa <host>` → lignes known_hosts offertes ;
   - pour chaque ligne, `ssh-keygen -lf <ligne>` → extrait « SHA256:… » (motif `re.search(r'SHA256:\S+')`,
     identique à `node_add.key_fingerprint`) ;
   - si UNE empreinte == `hostkey_sha256` → écrit CETTE ligne dans un known_hosts temporaire (0600) ;
   - sinon (aucune correspondance) → `RemoteProbeError` (MITM/mismatch), **aucun enrôlement**.
   *Justif :* on ne fait confiance à la clé offerte QUE parce que son empreinte égale celle déclarée
   hors-bande ; un MITM présente une clé dont l'empreinte diffère → refus (sûr, cf. §5 tests).

3. **Connexion.** `run()` lance `ssh -i <keyfile> -o BatchMode=yes -o StrictHostKeyChecking=yes -o
   UserKnownHostsFile=<temp> -o IdentitiesOnly=yes user@host -- argv`. Plus jamais `accept-new`.
   *Justif :* `=yes` + known_hosts pré-vérifié = ssh rejette toute clé ≠ celle enrôlée (anti-TOCTOU).

4. **Cycle de vie du known_hosts temporaire.** `tempfile` 0600, nettoyé (contexte/atexit) ; jamais
   `~/.ssh/known_hosts`. *Justif :* moindre privilège, pas de pollution ni de fuite inter-utilisateur.

5. **Surface CLI.** `node probe` et `node discover` (chemin distant) exigent `--hostkey SHA256:…`
   (cohérent avec `node tailscale`). Un appel sans empreinte ÉCHOUE proprement (code 12) — plus de TOFU.
   `node discover --hostname local` reste sans SSH (SubprocessRunner), donc sans `--hostkey`.
   *Justif :* toute connexion SSH distante exige désormais une identité d'hôte déclarée.

6. **Hors périmètre** : rotation de clés d'hôte, known_hosts hashé, multi-hôtes par runner, formats
   d'empreinte legacy MD5 (SHA256 seul accepté).

## 3. Stratégie TDAD (`tests/test_ssh007_hostkey.py` — RED d'abord)

Mock de `subprocess.run` par un dispatcher qui répond selon `argv[0]` (ssh-keyscan / ssh-keygen / ssh).

- **G1 refus sans empreinte** : `SshRunner(user, host, keyfile, hostkey_sha256="")` → `RemoteProbeError`,
  AUCUN `subprocess.run` (assert non appelé).
- **G2 refus empreinte mal formée** : `"pas-une-empreinte"` (sans « : ») → `RemoteProbeError` avant réseau.
- **G3 chemin heureux (match)** : keyscan renvoie une clé, ssh-keygen renvoie « SHA256:BON », `hostkey_sha256`
  = « SHA256:BON » → `run()` lance ssh avec `StrictHostKeyChecking=yes` et `UserKnownHostsFile=<temp>`,
  et l'argv NE contient PLUS `accept-new` ; le known_hosts temp contient exactement la ligne offerte.
- **G4 mismatch (MITM)** : ssh-keygen renvoie « SHA256:ATTAQUANT » ≠ attendue → `RemoteProbeError`,
  la commande ssh (argv métier) n'est JAMAIS lancée, aucun enrôlement.
- **G5 permissions/nettoyage** : le known_hosts temp est 0600 et supprimé en fin de vie.
- **G6 non-régression détectante** : muter `=yes` → `=accept-new` dans l'argv doit faire tomber G3
  (assert d'ABSENCE de `accept-new` + présence de `=yes`).
- **G7 les deux appelants** : `cli.main(["node","probe",…])` et `["node","discover",…]` sans `--hostkey`
  → code 12 (argparse required ou refus) ; `discover --hostname local` ne demande pas `--hostkey`.

## 4. Critères d'acceptation

- **CA1** `accept-new` totalement supprimé ; toute connexion SSH distante utilise `=yes` + known_hosts vérifié.
- **CA2** empreinte absente/mal formée → refus AVANT réseau (déterministe).
- **CA3** empreinte de la clé offerte ≠ déclarée → refus, aucun enrôlement, commande jamais lancée.
- **CA4** `node probe` et `node discover` (distant) exigent `--hostkey` ; `discover local` non.
- **CA5** known_hosts temp 0600, nettoyé ; jamais `~/.ssh/known_hosts`.
- **CA6** suite complète verte, no-stub, couverture ≥ 85 %.

## 5. Risques

- `ssh-keyscan` indisponible/pare-feu → l'enrôlement échoue proprement (refus, pas de fallback TOFU).
- Types de clé multiples (ed25519/ecdsa/rsa) : comparer l'empreinte de CHAQUE clé offerte à l'attendue.
- Empreinte hors-bande à obtenir par l'opérateur (doc) ; MD5 legacy hors périmètre.
- Course keyscan/connexion (rebind) : neutralisée par `=yes` + known_hosts figé (ssh revérifie à la connexion).
