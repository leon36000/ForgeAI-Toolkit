# WEB-015 — Normaliser les erreurs Web sans fuite d'exception interne

- **Issue** : #246 · **Tier** : T2 (sécurité — confidentialité : fuite d'exception interne au client HTTP)
- **Dépend de** : WEB-017 (garde GET) — mergé.
- **Reprise lane CODEX** · **Périmètre** : `src/forgeai/web/server.py`,
  `tests/test_web015_error_normalization.py` (nouveau), `tests/test_prepare_run_e2e.py`
  (conséquence : un test existant codifiait la fuite — `"kaboom inattendu" in erreur` — mis à jour
  pour asserter le message générique), `stories/WEB-015.md`.

## 1. Problème (code réel)
`do_GET`/threads renvoyaient la chaîne BRUTE d'exceptions internes au client HTTP :
- Quatre gardes `except Exception as exc` (INATTENDUES) : `/api/detect`, `/api/stacks/recommended`,
  `/api/discover?node=local` (inventaire), thread `preparer_noeud` — toutes sérialisaient `str(exc)`
  (chemins absolus, détails de pile, valeurs internes, potentiellement secrets).
- Deux sites `except ClusterError` (`/api/nodes/status`, `/api/nodes/receptacles`) exposaient
  `detail = str(exc)` ; or `ClusterError` (network/nodes.py:25) ENCAPSULE un `{exc}` interne
  (« sortie kubectl illisible : … »), donc l'exception sous-jacente fuyait via `detail`.

## 2. Décision (politique unique)
**Toute chaîne d'exception atteignant un client HTTP est soit générique (inattendue), soit rédigée
(domaine).**
- **Inattendu (`except Exception`, 4 sites)** : helper `_send_internal_error(exc)` — trace COMPLÈTE
  sur `stderr` via `traceback.print_exception(type(exc), exc, exc.__traceback__, …)` (imprime
  EXPLICITEMENT l'exception reçue, robuste hors bloc `except` — affinage de revue) + réponse client
  GÉNÉRIQUE `{"error": "erreur interne"}` (500). Aucun `str(exc)` au client. `redact_exception` a été
  écarté : il expose encore type+chemins non-secrets → « fuite d'exception interne » persistante.
- **ClusterError (domaine typé mais encapsule `{exc}`, 2 sites)** : `detail = redact_text(str(exc))`
  — le message de domaine (« cluster injoignable ») reste utile à l'UI (mode dégradé 200), mais tout
  secret encapsulé est neutralisé.

## 2b. Hors périmètre (documenté — cohérence contrat)
Les erreurs de domaine TYPÉES à message validé restent telles quelles : `NodeAddError` (400) est
DÉJÀ rédigée à la source (ERR-041C) ; `RouteError` (400) ne porte que des chaînes de validation
contrôlées (« route introuvable », « ttl_s doit être positif »). Génériser ces contrats utilisateur
retirerait un diagnostic voulu ; ce n'est pas l'objet de « sans fuite d'exception interne » (= les
exceptions INATTENDUES). Seul `ClusterError` est rédigé car il est le seul contrat à encapsuler un
`{exc}` brut de sous-processus.

## 3. TDAD (RED d'abord) — `tests/test_web015_error_normalization.py`
Serveur live loopback (style test_web_auth). Chaque fonction métier est patchée pour lever avec un
faux-secret/chemin ; le test EST le détecteur.
- **G1-G3** : `/api/detect`, `/api/stacks/recommended`, `/api/discover?node=local` → 500,
  corps EXACT `{"error":"erreur interne"}`, secret/chemin/type d'exception ABSENTS.
- **G4** : message générique exact (aucune clé en plus).
- **G5** : `stderr` contient la traceback (type réel) → l'opérateur garde le diagnostic (capfd).
- **G6** : `/api/nodes/status` ClusterError encapsulant un secret → 200 `nodes:[]`, `detail` rédigé
  (`«REDACTED»` présent, secret absent).
- **G7** : `/api/detect` nominal → 200 (non-régression).
- **Mutation** : réexposer `str(exc)` (helper + ClusterError) → G1-G4, G6 tombent (prouvé).

## 4. Critères d'acceptation
- **CA1** les 4 sites inattendus : réponse client générique `{"error":"erreur interne"}`, aucun
  `str(exc)` ; trace complète sur stderr.
- **CA2** les 2 sites ClusterError : `detail` rédigé (secret encapsulé neutralisé), message domaine préservé.
- **CA3** non-régression : chemins nominaux 200 inchangés ; erreurs de domaine 400 intactes ;
  suite complète verte, couverture ≥ 85 %.
