## Contexte (constat COPILOT, avant registration)

En vérifiant l'archivage rétroactif préparé par le cockpit (PR #222, branche
`chore/UI-040-archive-completion`, portée : ajouter à `coordination/completed.json` trois
packages CODEX mergés dans `main` mais jamais archivés — WEB-001 #199, DATA-002 #180,
DATA-003 #198), il a été confirmé que :

- Les trois merges sont réels, substantiels et déjà prouvés localement (tests, SonarCloud,
  Gitleaks verts, PR bodies détaillées) — **le code lui-même n'est pas remis en cause**.
- Les trois revues scellées associées (`reviews/WEB-001/**`, entrée `Registres/PATCH-DATA-002.jsonl`

  fournisseur : `gpt-5.6-sol` (rôles security + acceptance) et `gpt-5.6-terra` (rôle
  isolation/concurrency). Chaque entrée `completed.json` préparée par PR #222 le déclare
  honnêtement via un champ `vendor_claim` : *« OpenAI uniquement; aucune prétention
  multi-vendeur (not_multi_vendor=true, distinct_model_variants=2) »*.
- Ceci est un écart réel — mais **transparent et déjà signalé**, pas une fraude — vis-à-vis de
  la règle non négociable AGENTS.md/CLAUDE.md : *« reviewers = 3 vendors DISTINCTS ≠ vendor du
  codeur »* et de la revue aveugle scellée §3. PR #222 le documente explicitement et indique
  que « refaire la revue d'un autre IDE » est **hors périmètre cockpit** — d'où la création de
  ce package dédié, confié à `CLAUDE_CODE` (qui dispose du bridge LiteLLM multi-vendor).

## Ce qu'il faut faire

**Ne PAS recoder WEB-001/DATA-002/DATA-003.** Le seul travail est de rejouer, sur les diffs déjà
mergés, une revue aveugle scellée conforme (3 vendors distincts ≠ vendor du codeur, prompt
byte-identique, verdicts scellés sans accès mutuel) :

1. Pour chacun des 3 merges (`43a3617a` WEB-001/PR#199, `2ed262e2` DATA-002/PR#180, `828714b2`
   DATA-003/PR#198) : reconstruire le diff du merge (`git show <merge_commit>` ou
   `git diff <parent1>..<merge_commit>`), construire un pack avec
   `~/proof-method/scripts/pack_build.sh` (`PROOF_COMPRESS=0`).
2. Lancer `~/proof-method/scripts/civ_review.py --story reviews/<PKG>-revue2 --pack <pack>` avec
   3 vendors distincts du pool documenté (ex. `DeepSeek-V4-Pro, Gemini-3.1-Pro/MiMo-Pro-V2,
   LongCat-2.0`), aucun n'étant CODEX/OpenAI (le codeur d'origine).
3. Dépouiller avec `scripts/revue.py tally reviews/<PKG>-revue2` (exige `prompt_sha256` +
   3 vendors distincts, APPROVE-ssi-tous).
4. Mettre à jour l'entrée correspondante dans `coordination/completed.json` : remplacer/
   compléter le champ `review` avec le résultat de la nouvelle revue conforme (vendors,
   ratio, prompt_sha256, dossier), sans supprimer la trace de la revue OpenAI d'origine
   (conserver `vendor_claim` d'origine à titre d'historique, ou le déplacer dans un champ
   `superseded_review`).
5. Consigner chaque étape dans `Registres/PATCH-REV-043.jsonl` (`registre.py append ... --actor
   CLAUDE_CODE`), puis `verify`.
6. **Si le bridge LiteLLM / `civ_review.py` n'est pas joignable** dans l'environnement
   d'exécution : documenter honnêtement `BLOCKED-avec-raison` dans ce fichier et dans le
   registre — ne jamais fabriquer de verdicts ni de vendors.
