# HW-037 — Aligner la recommandation AMD/ROCm et supprimer le message mort

## Contexte

Package coordination HW-037 (issue #261, lane CLAUDE_CODE).
Dépendances : HW-010 livrée, CLI-036 en cours côté CODEX.

La story corrige un double désalignement entre la logique de recommandation livrée en HW-010 et son usage réel par la CLI.

1. Désalignement structurel.
   - `detect_driver_state`, seul chemin de production appelé par la CLI, appelait `recommend_driver(vendor)` sans transmettre le modèle GPU.
   - La logique par architecture livrée en HW-010 (`Instinct`/`CDNA`/`gfx9` → `rocm` ; `Radeon`/`RDNA` → `vulkan`) était donc inatteignable en production.
   - Mesure : `recommend_driver("amd", model="AMD Instinct MI300X")` renvoie bien `runtime == "rocm"`, mais le chemin CLI réel ne pouvait produire que le défaut `vulkan`.
   - Les tests unitaires passaient `model=` manuellement et masquaient le chemin réel.

2. Message mort.
   - La CLI imprimait en dur « (ROCm jamais proposé) » pour tout vendor `amd`.
   - Ce message contredisait l’état réel du moteur : `rocm_allowed=True`, `runtimes=("rocm", "vulkan")`, et la note « ROCm + Vulkan au choix ».
   - Aucun test ne couvrait cette chaîne complète de rendu.

## Décision

- `detect_driver_state` détecte désormais le modèle du GPU du vendor demandé via `HardwareDetector(runner).detect_gpus()`, avec le même runner injecté (`nvidia-smi` puis `lspci -nn`).
- Le modèle détecté est passé à `recommend_driver(vendor, model=...)`.
- Si aucun GPU du vendor n’est détecté, `model=None` et le comportement par défaut reste inchangé.
- L’affichage CLI est désormais dérivé du moteur :
  - runtime recommandé ;
  - opérateur ;
  - ordre des runtimes (`rocm > vulkan` ou `vulkan > rocm`) ;
  - note du moteur si présente.
- Plus aucune chaîne en dur n’affirme quoi que ce soit sur ROCm.
- Le payload JSON est enrichi avec `runtimes`.

## Critères d’acceptation

- [x] T1 : chemin réel Instinct → `recommendation.runtime == "rocm"` (ce test échouait avant le branchement ; il couvre le désalignement structurel).
- [x] T2 : chemin réel Radeon → `vulkan` par défaut, avec `rocm` présent dans les runtimes.
- [x] T3 : CLI publique amd/Instinct → sortie sans « jamais proposé », avec « runtime rocm » et « rocm > vulkan ».
- [x] T4 : CLI nvidia → « runtime cuda », sans aucune mention ROCm.
- [x] Les deux fakes préexistants ont été adaptés au nouvel appel `lspci` sans modifier leurs assertions.
- [x] Mutation : débrancher le modèle → T1 et T3 tombent.
- [x] Mutation : réintroduire le message mort → T3 tombe.

## Écart résiduel (à ne pas masquer)

L’exécution du plan d’installation des drivers attend CLI-036 (CODEX : runner borné et annulable).

La présente story couvre uniquement la recommandation et son affichage, pas l’exécution.

Le package coordination sera marqué `completed` via la coordination centrale après fusion, conformément à la note du package.
