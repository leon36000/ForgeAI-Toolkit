# RC1-018 — Gate wheel/sdist installable et testable hors checkout (issue #448)

## Contexte
Parent #428. Dépend de #447 (matrice Python 3.10–3.13 + lockfile à empreintes, livrée et
fusionnée). Source audit externe : EXT-022, EXT-035.

La CI ne testait jusqu'ici que le checkout : le contrat de l'artefact réellement distribué
(wheel/sdist construits par `python -m build`) n'était vérifié nulle part, ni bloquant à aucun
changement. L'audit externe avait confirmé que le wheel *peut* fonctionner, sans garantie
qu'il continue de fonctionner à chaque merge.

## Critères d'acceptation
1. Construire wheel et sdist avec un outil versionné (`build==1.2.2.post1`).
2. Inspecter métadonnées, fichiers embarqués et absence de fichiers inattendus.
3. Installer chaque artefact dans un environnement propre hors checkout.
4. Exécuter `forgeai --help`, `doctor`, démarrage Web local et chargement du catalogue —
   mêmes contrôles sur **chaque** artefact (wheel ET sdist), pas seulement l'un des deux.
5. Vérifier package-data, locales, stacks et assets Web.
6. Désinstaller puis confirmer qu'aucun fichier du paquet ne subsiste.
7. Construire deux fois sous `SOURCE_DATE_EPOCH` fixé et comparer les artefacts (reproductible).
8. Publier les résultats et empreintes comme artefacts CI.
9. Test négatif : retirer volontairement un package-data pour prouver que le gate le détecte
   (par mutation réelle, pas par inspection de code).

Le job doit tester l'artefact **distribué** (installé depuis le wheel/sdist), jamais importer
le code directement depuis `src/`.

## Notes d'implémentation
- `scripts/verifier_artefact_distribue.py` (stdlib pur) : règles DIFFÉRENCIÉES par format — un
  wheel ne doit pas contenir `tests/`, un sdist le doit (c'est ce qui rend le sdist testable
  après désarchivage) ; les artefacts de gouvernance (`evidence/`, `governance/`, `.github/`)
  et les `__pycache__` restent interdits dans les deux formats.
- `.github/workflows/artefact-distribue.yml` : workflow CI dédié, volontairement pas dans
  `gates.yml` (isolation des lanes actives au moment de la story).
- Preuves mesurées sur les artefacts réels du dépôt : wheel (116 fichiers) → exit 0 ; sdist
  (332 membres) → exit 0 ; test négatif (critère 9) prouvé par mutation réelle — en retirant
  `forgeai/data/locales/{en,fr}.json` du wheel, le vérificateur sort en 1 en nommant le
  package-data manquant.
- Revue scellée round 1 (RC1-448-PR506-v1) : REJECT 2/3 — une objection sur le sdist non
  symétrisé au wheel (critère 4, fondée, corrigée par une fonction `verifier_artefact()`
  appelée deux fois plutôt que dupliquée) et une sur un import de test supposément invalide
  (réfutée : `pyproject.toml` déclare `pythonpath = ["src", "scripts"]`).
- Revue scellée round 2 (RC1-448-PR506-v2) : APPROVE 3/3 (google/alibaba/xiaomi, codeur
  openai/GPT-5.6-Terra-Pro), zéro objection. La CI du workflow lui-même a alors révélé un bug
  d'outillage distinct de la story : `python -m build --no-isolation` échoue depuis Python 3.12
  (`setuptools.build_meta` non préinstallé) — corrigé en retirant `--no-isolation`, laissant
  `build` provisionner lui-même le backend déclaré par `pyproject.toml` (voir round de revue
  suivant pour la re-confirmation post-correctif).
- Branche reconstruite (squash) sur `origin/main` courant après 345 commits de retard incluant
  la migration structurelle RC1-010 (#440, `reviews/` → `evidence/reviews/`) — voir le message
  du commit de code pour le détail ; historique original préservé dans
  `backup/RC1-448-pre-reconstruction`.
