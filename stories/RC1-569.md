# Story RC1-569 — `_diff_canonique` doit forcer `--no-abbrev` (issue #569)

Tier: T1 (outillage de gouvernance, ne touche pas `src/forgeai/`)

Origine : découvert en tentant de merger #568 (issue #463) — le gate CI `reviews-sealed`
échouait avec « diff modifié après revue » alors que le check local identique
(`scripts/reviews_gate.py --exiger-recu-courant --base-ref origin/main`) rapportait « GATE OK »
sur EXACTEMENT le même commit.

## Cause racine (reproduite et isolée empiriquement)

`_diff_canonique` (scripts/revue.py) appelait `git diff --raw --no-renames -z` SANS
`--no-abbrev`. Le format `--raw` de git abrège les hash d'objet à la longueur la PLUS COURTE
jugée unique — heuristique qui dépend du NOMBRE TOTAL D'OBJETS du dépôt LOCAL (donc de
l'historique de fetch de la machine qui exécute), pas seulement du contenu des deux extrémités
du diff.

Reproduit : le même diff logique (`origin/main...HEAD` sur #568) donnait des hash abrégés de
longueurs DIFFÉRENTES entre un worktree partageant le `.git` du dépôt principal (~22820 objets,
abrégés à 8 caractères) et un clone frais depuis GitHub (~12584 objets, abrégés à 7 caractères)
— alors que `origin/main`, le merge-base et le nombre de lignes de diff étaient identiques dans
les deux.

`--full-index` (tenté en premier) NE corrige PAS ce cas : ce flag ne s'applique qu'au format
patch normal (ligne `index aaaa..bbbb` d'un `git diff` sans `--raw`), jamais au format `--raw`
lui-même. Le flag correct pour `--raw` est `--no-abbrev` — vérifié : avec ce flag, worktree et
clone frais produisent des hash SHA-1 complets (40 caractères) strictement identiques pour le
même diff logique.

## Impact avant correctif

Tout reçu D9 (`revue.py recu`) généré sur une machine locale (worktree partageant l'object-store
du dépôt principal, usage courant dans cette campagne) pouvait avoir un `diff_digest` ne
correspondant PAS à celui recalculé par un clone frais (comme `actions/checkout` en CI) — le
gate `reviews-sealed` pouvait alors rejeter à tort un reçu pourtant généré sur un changement
correctement revu et approuvé 3/3, bloquant le merge sans raison de fond.

## Périmètre

1. `scripts/revue.py`, fonction `_diff_canonique` : ajouter `--no-abbrev` à l'appel
   `git diff --raw`.

## Explicitement hors périmètre

- Toute autre partie de `scripts/revue.py` ou `scripts/reviews_gate.py` — non touchée.
- Les 2 warnings pytest visibles dans la suite complète de CE worktree (`test_rel038b_unicite.py`)
  : proviennent de #463/PR #568, pas encore mergée à la racine de cette branche — non lié à ce
  correctif, se résorbe naturellement une fois #463 mergée.
