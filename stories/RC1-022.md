# Story RC1-022 — Politique de warnings pytest (issue #463)

Tier: T0 (test only, ne touche pas la logique produit dans `src/forgeai/`)

Origine : audit maximal EXT-026, issue GitHub #463 (« Improve pytest warning policy », parent #428).
Mesuré : `python3 -m pytest -q` (suite complète, 100% verte, 0 échec) affiche exactement 2
warnings identiques `PytestUnhandledThreadExceptionWarning`, tous deux issus de
`tests/test_rel038b_unicite.py::test_g4_hote_libere_meme_sur_exception_non_rattrapee`. Ce test
lève délibérément un `KeyboardInterrupt` (`BaseException`) dans un thread de fond pour prouver
que le `finally` de `_run_prepare` (`src/forgeai/web/server.py`) libère l'hôte même quand
l'exception échappe à `except Exception`. Le warning est un effet de bord non déclaré du test —
pas un bug applicatif.

## Problème

1. Le test ne déclare pas explicitement qu'il s'attend à ce warning : celui-ci « fuit » comme
   bruit non contractuel dans la sortie CI.
2. Aucune politique globale ne transforme un `PytestUnhandledThreadExceptionWarning` INATTENDU
   (un vrai bug de thread ailleurs dans la suite) en échec — il passerait aujourd'hui inaperçu.

## Critères d'acceptation (issue #463)

1. `python3 -m pytest -q tests/test_rel038b_unicite.py -k test_g4` : PASS, 0 warning affiché.
2. `python3 -m pytest -q` (suite complète, hors `test_data002b_wal_idempotent.py` — problème
   distinct) : 100% vert, section « warnings summary » absente.
3. Preuve négative (mécanisme round v12, corrélation par identité thread+exception) — précision
   demandée par la revue scellée (round v12, DeepSeek, majeure retenue : l'affirmation initiale
   était imprécise sur ce que le sabotage démontre réellement) :
   - Sabotage testé : retrait du `raise` dans `faux_preparer_qui_echappe`. L'auto-enregistrement
     dans `exceptions_attendues` (l'INTENTION de lever, capturée AVANT le `raise`) reste, lui,
     inchangé. Résultat observé : `exceptions_interceptees` reste vide (rien n'atteint jamais
     `threading.excepthook`), donc `assert exceptions_interceptees == exceptions_attendues`
     échoue avec un diff explicite (`[] vs 1 entrée`). Ce sabotage précis démontre que « rien n'a
     été levé » se traduit en échec observable — PAS spécifiquement « levée mais rattrapée plus
     haut dans la pile », scénario qui exigerait de modifier `_run_prepare` pour être simulé
     (hors périmètre, non testé ici).
   - Ce que le MÉCANISME rend possible structurellement, au-delà de ce sabotage précis :
     `exceptions_attendues` capture l'intention de lever (avant le `raise`), `exceptions_interceptees`
     exige l'ARRIVÉE RÉELLE à `threading.excepthook` — si une future modification de
     `_run_prepare` rattrapait `BaseException` entre les deux, les deux listes divergeraient de
     la même façon. Hypothèse plausible au vu de la conception, non vérifiée par un test dédié.
   - Filet de sécurité structurel (répond à l'objection round v12, DeepSeek, critique) : toute
     exception de thread NON reconnue par la corrélation d'identité est déléguée à
     `hook_precedent` (le hook pytest normal) — si la corrélation échouait à tort à reconnaître
     une exception réellement issue de `faux_preparer_qui_echappe`, elle remonterait comme
     `PytestUnhandledThreadExceptionWarning` normal et ferait ÉCHOUER le test via la politique
     globale `error::...`. Un défaut de corrélation ne peut donc pas passer inaperçu — il n'a pas
     besoin d'être prouvé séparément, il est structurellement rattrapé par le gate déjà en place.
   - Restauration de `threading.excepthook` — vérifiée empiriquement sur LES DEUX chemins (pas
     seulement supposée, contrairement à l'affirmation initiale du round v12) : identité (`is`)
     confirmée entre la valeur avant et après un run pytest isolé de `test_g4`, à la fois en cas
     de SUCCÈS et en cas d'ÉCHEC (sabotage) — `IDENTIQUE apres UN ECHEC: True`, exit pytest 1
     comme attendu (preuve dans le commit round v13).
4. `pyproject.toml` reste un TOML valide (`python3 -c "import tomllib; tomllib.load(open('pyproject.toml','rb'))"`).
5. `python3 scripts/no_stub_scan.py --all` passe.
6. Aucun secret, aucune donnée inventée dans le diff.
