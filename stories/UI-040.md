## Root cause (analysée — critères d'acceptation #1 à #4)

Trois manques d'accessibilité mineurs sur des fondamentaux par ailleurs solides
(`:focus-visible`, `lang`, `aria-*` déjà présents, confirmé par l'audit) :
1. **Aucun skip-link** : un utilisateur au clavier devait tabuler à travers tout l'en-tête
   (logo, sélecteurs langue/thème) avant d'atteindre le contenu principal à chaque page.
2. **Aucun `prefers-reduced-motion`** : les transitions CSS (`.btn`, `.step-item`, etc.)
   s'appliquaient inconditionnellement, sans respecter le réglage système de réduction de
   mouvement (potentiellement gênant/nauséogène pour les utilisateurs concernés).
3. **Couleur d'erreur borderline AA** : `#E5533D` atteignait ~3.4-3.7:1 selon le fond en thème
   clair, sous le seuil WCAG AA de 4.5:1 pour texte normal (mesuré précisément dans cette
   session, confirmant l'audit).

## Limites / non fait dans cette branche

- Le libellé du skip-link est bilingue mais **hors du mécanisme `data-i18n` standard** (deux
  `<span>` statiques + bascule CSS), car les fichiers de locale sont hors périmètre de ce
  correctif — cohérent avec la même contrainte déjà rencontrée et documentée dans `UI-039`.
- `--accent` (utilisé pour d'autres éléments, ex. `.btn.active`) présente lui aussi un
  contraste ~4.28:1 en thème clair (sous AA strict pour texte normal, bien qu'au-dessus du
  seuil AA pour texte large/composants UI selon WCAG 1.4.11). Non corrigé ici : hors périmètre
  strict de `FAI-U-040`, qui cible spécifiquement la couleur d'erreur (`app.css:74,328`) — une
  revue plus large de la palette d'accent serait un package séparé.
- Aucun test avec navigateur réel (Playwright/Selenium) : non disponible dans l'environnement
  et l'ajout d'une telle dépendance est hors périmètre (`allowed_paths` n'inclut aucun fichier
  de dépendances). Vérification par analyse statique programmatique (calcul WCAG réel en
  Python, extraction structurelle CSS/HTML), cohérent avec le style déjà établi de
  `tests/test_web_i18n.py` (`test_focus_visible_present`).
