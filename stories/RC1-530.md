# RC1-530 — `_valider_adopt` lève ValueError sur un port Unicode non-ASCII (issue #530)

## Contexte
`_valider_adopt` (`src/forgeai/web/server.py:202-241`) valide le champ `adopt` de
`POST /api/deploy`. Elle teste `port.isdigit()` puis appelle `int(port)`. `str.isdigit()`
accepte des caractères Unicode « chiffre » (ex. `²` U+00B2) que `int()` ne sait pas parser →
`ValueError` non rattrapée qui remonte hors de `do_POST`, tuant le thread de connexion sans
réponse HTTP — déni de service par requête malformée. Le commentaire du code (lignes 1407-1411)
documente déjà l'intention contraire : une `ValueError` qui remonte donnerait un 500 sur une
simple faute de saisie ; `_valider_adopt` doit toujours retourner une chaîne d'erreur.

## Critères d'acceptation
1. `_valider_adopt` ne lève jamais d'exception pour un port invalide quel qu'il soit (Unicode
   ou ASCII) — retourne systématiquement une chaîne d'erreur.
2. Le message d'erreur pour un port non convertible reste identique à l'existant (« port non
   numerique ») — aucune régression de contrat pour l'appelant.
3. Comportement inchangé pour tout port déjà valide (ASCII 1-65535) et tout cas déjà couvert
   (port hors bornes, port non numérique ASCII).
4. Preuve en conditions réelles : un serveur HTTP démarré (pas mocké) reçoit une requête
   `POST /api/deploy` avec un port Unicode invalide et répond **400** avec un corps JSON
   `{"error": ...}` — jamais un timeout/RemoteDisconnected, jamais un 500.
5. TDD : `tests/test_rc530_port_unicode_crash.py` écrit avant le correctif, confirmé ROUGE
   contre le code buggy (reproduit le `RemoteDisconnected` réel de l'issue), puis VERT après.
6. Zéro régression sur les suites de tests existantes touchant `_valider_adopt`/`do_POST`
   (`tests/test_web_deploy.py`, `tests/test_adoption_api.py`, `tests/test_web_server.py`,
   `tests/test_deploy_units.py`) et sur la suite complète.

## Notes d'implémentation
Correctif minimal (2 lignes) via `crew_dispatch.py` (Kimi-K3/GPT-5.6-Luna-Pro selon
disponibilité passerelle) : remplace `if not port.isdigit(): ...; p = int(port)` par
`try: p = int(port); except ValueError: return ...` — même message d'erreur, aucun autre
comportement modifié. Le codeur a initialement livré une réécriture complète non sollicitée de
la fonction (perte de la validation d'hôte, appel à `_clip` non défini) — rejetée ; seul le
correctif ciblé de 2 lignes a été appliqué manuellement à l'Edit.
